Open RC1 release Setup details

Este es el hogar de eMuleBB: eMule broadband edition, un producto independiente para quienes todavía valoran el modelo de compartición distribuida de eMule y quieren operarlo como software moderno. Los paquetes RC1 están publicados en GitHub Releases con un bootstrapper de suite completa, ZIPs independientes, manifiestos, hashes, SBOMs y los assets de controlador aMuTorrent correspondientes.

Por qué

El software P2P gana confianza sobreviviendo a sesiones reales

eMuleBB es a la vez un esfuerzo de producto y una práctica de ingeniería: conservar un cliente nativo de Windows complejo con comportamiento de red real y rodearlo de builds, pruebas, documentación, automatización y evidencia de release modernos.

Motivo de producto

eMuleBB es su propio producto

El objetivo no es un mod cosmético, un fork de protocolo ni una carcasa de descargas genérica. Es una línea eMule orientada a la banda ancha para sesiones largas, archivos raros, seeding deliberado y usuarios avanzados que aún quieren el workflow de escritorio nativo.

Motivo técnico

Hacer inspeccionable el comportamiento P2P

Los slots de upload, timeouts, buffers, bibliotecas grandes, exposición de WebServer, control REST y evidencia de paquetes se hacen explícitos para poder revisar, probar, documentar y ajustar cada cambio.

Motivo de ecosistema

Construir las herramientas alrededor del cliente

La misma disciplina de workspace cubre la app, el tooling de controladores, los builds de Windows, los servicios eD2K deterministas y el trabajo experimental headless de eD2K/Kad sin pretender que cada proyecto de laboratorio sea un producto estable para usuarios finales.

Funciones

Lo que eMuleBB añade alrededor del cliente clásico

El trabajo de RC1 se centra en el comportamiento visible para el operador: política de upload predecible, binding más seguro, límites fijos de rendimiento, operación de bibliotecas grandes, automatización local y evidencia de paquetes.

Compartir y upload

Control de upload en banda ancha

Objetivos acotados de slots, reciclaje de slots débiles, lecturas de ratio y controles de seeding mantienen útiles los enlaces de upload rápidos sin cambiar el protocolo de upload eD2K.

Control de red

Binding, NAT y política de exposición

El binding consciente de la interfaz, la validación de mapeo UPnP/NAT, HTTPS, las reglas de IP permitida y los ajustes de bind separados de WebServer mantienen las superficies remotas explícitas y comprobables. El binding no es un kill switch de VPN.

Rendimiento y escala

Valores actuales para sesiones grandes

Buffers de socket mayores, límites de queue/source, file buffering, valores de timeout, sincronización recursiva de compartidos, trabajo de caché de arranque y guía de long paths apuntan a los sistemas Windows actuales y a las bibliotecas grandes.

Red clásica

eD2K y Kad siguen primero

La búsqueda Server, global y Kad sigue siendo la base nativa, con seguimiento de identidad Kad, manejo de nodos malos, limpieza y trabajo de timing mantenidos dentro de los límites de compatibilidad.

Automatización

Workflows de REST y controladores

Los endpoints JSON autenticados cubren transferencias, búsquedas, archivos compartidos, servidores, Kad, logs, categorías, uploads, estadísticas, preferencias y apagado controlado desde herramientas locales de confianza.

Seguridad y procedencia

RC1 se construye y empaqueta en GitHub

RC1 publicado

emulebb-v0.7.3-rc.1 es una prerelease de GitHub con ZIPs x64 y ARM64, paquetes de diagnóstico, manifiestos, SBOMs y el bootstrapper de la suite.

Instalación verificada por hash

El bootstrapper descarga los assets del release y verifica los hashes de los paquetes a partir de los manifiestos publicados antes de instalar.

Assets de la suite

El paquete aMuTorrent RC1 correspondiente se publica por separado, y el flujo de bootstrap x64 completo lo resuelve automáticamente para configurar el controlador.

SPDX SBOM

Release packages carry package-local SBOM.spdx.json plus sidecar *.sbom.spdx.json files, with manifest hashes that tie software contents to the exact package evidence.

GitHub provenance

RC1 assets are published from GitHub release automation with manifests, SHA-256 evidence, SBOMs, and a bootstrapper hash asset for verification.

Prueba de controladores

aMuTorrent, Prowlarr, Radarr, Sonarr, Torznab y los carriles compatibles con qBittorrent están documentados como vías de integración local en torno al contrato nativo /api/v1.
