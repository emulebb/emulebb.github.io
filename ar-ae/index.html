لماذا

تكسب برمجيات P2P الثقة بالنجاة من الجلسات الحقيقية

eMuleBB جهد منتج وممارسة هندسية في آن واحد: الحفاظ على عميل Windows أصلي معقّد بسلوك شبكي حقيقي، ثم إحاطته ببُنى واختبارات وتوثيق وأتمتة وأدلة إصدار حديثة.

سبب يتعلق بالمنتج

eMuleBB منتج مستقل بذاته

الهدف ليس تعديلًا شكليًا ولا تفرّعًا للبروتوكول ولا قشرة تنزيل عامة. إنه خط eMule موجّه للنطاق العريض للجلسات الطويلة والملفات النادرة والبذر المتعمّد والمستخدمين المتقدمين الذين ما زالوا يريدون سير عمل سطح المكتب الأصلي.

جعل سلوك P2P قابلًا للفحص

خانات الرفع والمهل الزمنية والمخازن المؤقتة والمكتبات الكبيرة وكشف WebServer والتحكم عبر REST وأدلة الحزم تُجعل صريحة لكي يمكن مراجعة كل تغيير واختباره وتوثيقه وضبطه.

يشمل انضباط الـ workspace نفسه التطبيق وأدوات التحكم وبُنى Windows وخدمات eD2K الحتمية والعمل الاستكشافي بلا واجهة لـ eD2K/Kad دون التظاهر بأن كل مشروع مختبري منتج مستقر للمستخدم النهائي.

الميزات

ما يضيفه eMuleBB حول العميل الكلاسيكي

يركّز عمل RC1 على السلوك المرئي للمشغّل: سياسة رفع متوقعة وbinding أكثر أمانًا وحدود أداء ثابتة وتشغيل المكتبات الكبيرة والأتمتة المحلية وأدلة الحزم.

المشاركة والرفع

التحكم في الرفع عريض النطاق

أهداف خانات محدودة وإعادة تدوير الخانات الضعيفة وقراءات النسبة وضوابط البذر تُبقي روابط الرفع السريعة مفيدة دون تغيير بروتوكول الرفع eD2K.

التحكم في الشبكة

Binding وNAT وسياسة الكشف

binding مدرك للواجهة والتحقق من تعيين UPnP/NAT وHTTPS وقواعد عناوين IP المسموح بها وإعدادات ربط WebServer المنفصلة تُبقي الأسطح البعيدة صريحة وقابلة للاختبار. الـ binding ليس مفتاح إيقاف VPN.

الأداء والحجم

إعدادات افتراضية حديثة للجلسات الكبيرة

مخازن مقابس أكبر وحدود queue/source وتخزين الملفات المؤقت وقيم المهل الافتراضية والمزامنة التكرارية للمشاركات وعمل ذاكرة بدء التشغيل وإرشادات المسارات الطويلة تستهدف أنظمة Windows الحالية والمكتبات الكبيرة.

الشبكة الكلاسيكية

يبقى eD2K وKad في المقدمة

يبقى البحث عبر الخادم والبحث العام وبحث Kad الأساس الأصلي، مع تتبّع هوية Kad ومعالجة العقد السيئة والتنظيف وعمل التوقيت ضمن حدود التوافق.

الأتمتة

سير عمل REST والمتحكمات

تغطي نقاط نهاية JSON المصادَق عليها النقل والبحث والملفات المشتركة والخوادم وKad والسجلات والفئات والرفع والإحصاءات والتفضيلات والإيقاف المتحكَّم به من أدوات محلية موثوقة.

انضباط الاختبار والإصدار

يُنشر 0.7.3-rc.1 مع تغليف GitHub Actions وبيانات وأدلة SHA-256 وملفات SBOM بصيغة SPDX وأصول تشخيص وأدلة تجزئة المُمهِّد.

الوثائق

أدلة وواجهة API وملاحظات الإصدار

01

ابدأ بدليل المنتج

شغّل eMuleBB كـ eMule أولًا: خوادم موثوقة وbootstrap متعمّد لـ Kad ومسارات incoming/temp متوقعة ومجلدات مشتركة مرئية.

02

استخدم الأتمتة المحلية

فعّل REST للمتحكمات الموثوقة فقط، ثم استخدم aMuTorrent وProwlarr وRadarr وSonarr عبر مسارات المحوّلات الموثّقة.

03

اقرأ الدليل

تفاصيل الإعداد وواجهة API والإصدار وSBOM والحزم موجودة في الوثائق المُصيَّرة لتبقى الادعاءات العامة مرتبطة بأدلة خاضعة للتحكم في الإصدارات.

يعرض مسار الإصدار عريض النطاق واجهة JSON API موجّهة للموارد /api/v1 من مستمع WebServer الحالي. تُصادِق عبر X-API-Key وتُقدّم أغلفة JSON وتُبقي تغييرات حالة eMule الأصلية موجَّهة عبر التطبيق.

دليل الإعداد نموذج التثبيت وسلوك الملف الشخصي عند أول تشغيل وملاحظات بدء عملية. دليل منتج eMuleBB الإعداد والضبط والأتمتة والاستخدام المدرك للإصدار والاختبار وأدلة SBOM. استخدام aMuTorrent مع eMuleBB إعداد موجّه للمهام لـ eMuleBB وaMuTorrent وProwlarr وRadarr وSonarr. دليل المتحكمات وREST استخدام متحكمات محلية موثوقة وحدود الأتمتة. دليل التنزيل والبحث أوضاع البحث والثقة في النتائج والفئات وسير عمل ملفات المستخدمين المتقدمين. وكيل eMule لـ p2p-overlord حدود وكيل Rust بلا واجهة لـ Kad/eD2K، ووثائق المصدر، وملاحظات عقد eMuleBB. لوحة إصدار 0.7.3 بوابات RC الحالية وأدلة الاختبار الآلي وأدلة SBOM/الحزم وقواعد الجاهزية.

الأمان والمصدر

يُبنى RC1 ويُحزَّم على GitHub

RC1 المنشور

emulebb-v0.7.3-rc.1 هو إصدار GitHub مسبق يضم ملفات ZIP لـ x64 وARM64 وحزم تشخيص وبيانات وملفات SBOM ومُمهِّد الحزمة.

إعداد مُتحقَّق بالتجزئة

يقوم المُمهِّد بتنزيل أصول الإصدار والتحقق من مجموعات تجزئة الحزم من البيانات المنشورة قبل التثبيت.

أصول الحزمة

تُنشر حزمة aMuTorrent RC1 المطابقة على حدة، ويحلّها مسار bootstrap الكامل لـ x64 تلقائيًا لإعداد المتحكم.

SPDX SBOM

Release packages carry package-local SBOM.spdx.json plus sidecar *.sbom.spdx.json files, with manifest hashes that tie software contents to the exact package evidence.

GitHub provenance

RC1 assets are published from GitHub release automation with manifests, SHA-256 evidence, SBOMs, and a bootstrapper hash asset for verification.
