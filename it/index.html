Perché

Il software P2P guadagna fiducia sopravvivendo a sessioni reali

eMuleBB è insieme uno sforzo di prodotto e una pratica di ingegneria: preservare un client Windows nativo complesso con comportamento di rete reale e poi circondarlo di build, test, documentazione, automazione e prove di release moderni.

Motivo di prodotto

eMuleBB è un prodotto a sé

L'obiettivo non è un mod cosmetico, un fork di protocollo o un guscio di download generico. È una linea eMule orientata alla banda larga per sessioni lunghe, file rari, seeding deliberato e power user che vogliono ancora il workflow desktop nativo.

Motivo tecnico

Rendere ispezionabile il comportamento P2P

Slot di upload, timeout, buffer, grandi librerie, esposizione WebServer, controllo REST e prove di pacchetto sono resi espliciti, così ogni modifica può essere revisionata, testata, documentata e regolata.

Motivo di ecosistema

Costruire gli strumenti attorno al client

La stessa disciplina di workspace copre l'app, il tooling per controller, i build Windows, i servizi eD2K deterministici e il lavoro sperimentale headless eD2K/Kad senza fingere che ogni progetto di laboratorio sia un prodotto stabile per l'utente finale.

Funzioni

Cosa aggiunge eMuleBB attorno al client classico

The stable 0.7.3 line is focused on operator-visible behavior: predictable upload policy, safer binding, fixed performance limits, large-library operation, local automation, and package evidence.

Condivisione e upload

Controllo upload per banda larga

Target limitati per gli slot, riciclo degli slot deboli, lettura dei ratio e controlli di seeding mantengono utili gli upload veloci senza cambiare il protocollo di upload eD2K.

Controllo rete

Binding, NAT e policy di esposizione

Il binding consapevole dell'interfaccia, la validazione del mapping UPnP/NAT, HTTPS, le regole di IP consentito e impostazioni di bind WebServer separate mantengono le superfici remote esplicite e testabili. Il binding non è un kill switch VPN.

Prestazioni e scala

Default attuali per sessioni grandi

Buffer socket più grandi, limiti queue/source, file buffering, default di timeout, sync ricorsiva delle condivisioni, lavoro di cache all'avvio e indicazioni sui long path mirano ai sistemi Windows attuali e alle grandi librerie.

Rete classica

eD2K e Kad restano al primo posto

La ricerca Server, globale e Kad resta la base nativa, con tracciamento dell'identità Kad, gestione dei nodi cattivi, cleanup e lavoro di timing mantenuti entro i confini di compatibilità.

Automazione

Workflow REST e di controllo

Endpoint JSON autenticati coprono trasferimenti, ricerche, file condivisi, server, Kad, log, categorie, upload, statistiche, preferenze e shutdown controllato da strumenti locali fidati.

Security and provenance

0.7.3 is built and packaged on GitHub

Published 0.7.3

emulebb-v0.7.3 is a stable GitHub release with x64 and ARM64 ZIPs, diagnostics packages, manifests, SBOMs, and the suite bootstrapper.

Hash-checked setup

The bootstrapper downloads release assets and verifies package hashes from the published manifests before installing.

Suite assets

The matching aMuTorrent 0.7.3 companion package is published separately, and the full x64 bootstrap flow resolves it automatically for controller setup.

SPDX SBOM

Release packages carry package-local SBOM.spdx.json plus sidecar *.sbom.spdx.json files, with manifest hashes that tie software contents to the exact package evidence.

GitHub provenance

Stable 0.7.3 assets are published from GitHub release automation with manifests, SHA-256 evidence, SBOMs, and a bootstrapper hash asset for verification.

Controller proof

aMuTorrent, Prowlarr, Radarr, Sonarr, Torznab, and qBittorrent-compatible lanes are documented as local integration paths around the native /api/v1 contract.
