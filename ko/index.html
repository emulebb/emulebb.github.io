현재 베타 테스트에는 eMuleBB Rust nightly를 사용하세요. 고정된 공식 기준이 필요하면 공개 0.1.0-beta.2를 사용하세요. MFC 0.7.3은 유지보수 중인 Windows 라인에만 사용합니다.

이곳은 eMuleBB의 본거지입니다. eMule broadband edition은 eMule의 분산 공유 모델을 여전히 소중히 여기고 그것을 현대적인 소프트웨어처럼 운영하고 싶은 사람들을 위한 독립 제품입니다. 0.7.3 패키지는 풀 스위트 부트스트래퍼, 독립 ZIP, 매니페스트, 해시, SBOM, 그리고 대응하는 aMuTorrent 컨트롤러 자산과 함께 GitHub Releases에 공개되어 있습니다.

왜

P2P 소프트웨어는 실제 세션을 견뎌내며 신뢰를 얻습니다

eMuleBB는 제품적 노력이자 엔지니어링 실천입니다. 실제 네트워크 동작을 지닌 복잡한 네이티브 Windows 클라이언트를 보존하고, 그것을 현대적인 빌드, 테스트, 문서, 자동화, 릴리스 증거로 둘러쌉니다.

제품적 이유

eMuleBB는 독립적인 제품

목표는 겉모습만 바꾼 mod, 프로토콜 포크, 일반적인 다운로더 셸이 아닙니다. 긴 세션, 희귀한 파일, 의도적인 시딩, 그리고 여전히 네이티브 데스크톱 워크플로를 원하는 파워 유저를 위한 광대역 중심의 eMule 라인입니다.

엔지니어링 이유

P2P 동작을 검사 가능하게 만들기

업로드 슬롯, 타임아웃, 버퍼, 대규모 라이브러리, WebServer 노출, REST 제어, 패키지 증거를 명시적으로 만들어 각 변경을 검토·테스트·문서화·조정할 수 있게 합니다.

생태계 이유

클라이언트 주위에 도구를 구축하기

동일한 workspace 규율이 활성 베타 eMuleBB Rust, 컨트롤러 도구, Windows 빌드, 결정적 eD2K 서비스, 유지보수 중인 MFC 라인을 아우릅니다.

기능

eMuleBB가 기존 클라이언트 주위에 더하는 것

0.7.3 작업은 운영자에게 보이는 동작에 초점을 둡니다. 예측 가능한 업로드 정책, 더 안전한 binding, 고정된 성능 한계, 대규모 라이브러리 운영, 로컬 자동화, 패키지 증거입니다.

공유 및 업로드

광대역 업로드 제어

한정된 슬롯 목표, 약한 슬롯 재활용, 비율 표시, 시딩 제어가 eD2K 업로드 프로토콜을 바꾸지 않고도 빠른 업로드 회선을 유용하게 유지합니다.

네트워크 제어

Binding, NAT, 노출 정책

인터페이스를 인식하는 binding, UPnP/NAT 매핑 검증, HTTPS, 허용 IP 규칙, 별도의 WebServer 바인드 설정이 원격 표면을 명시적이고 테스트 가능하게 유지합니다. binding은 VPN 킬 스위치가 아닙니다.

성능과 규모

대규모 세션을 위한 현대적 기본값

더 큰 소켓 버퍼, queue/source 한계, 파일 버퍼링, 타임아웃 기본값, 재귀 공유 동기화, 시작 시 캐시 작업, 긴 경로 안내가 현재의 Windows 시스템과 대규모 라이브러리를 대상으로 합니다.

클래식 네트워크

eD2K와 Kad가 우선

서버, 글로벌, Kad 검색은 네이티브 기반으로 남아 있으며, Kad 신원 추적, 불량 노드 처리, 정리, 타이밍 작업은 호환성 경계 안에 유지됩니다.

자동화

REST 및 컨트롤러 워크플로

인증된 JSON 엔드포인트는 신뢰된 로컬 도구로부터의 전송, 검색, 공유 파일, 서버, Kad, 로그, 카테고리, 업로드, 통계, 환경설정, 제어된 종료를 다룹니다.

테스트와 릴리스 규율

라벨보다 증거 먼저

0.7.3은 GitHub Actions 패키징, 매니페스트, SHA-256 증거, SPDX SBOM, 진단 자산, 부트스트래퍼 해시 증거와 함께 공개됩니다.

문서

가이드, API, 릴리스 노트

01

제품 가이드부터 시작하기

먼저 eMuleBB를 eMule처럼 사용하세요. 신뢰할 수 있는 서버, 의도적인 Kad bootstrap, 예측 가능한 incoming/temp 경로, 보이는 공유 폴더입니다.

02

로컬 자동화 사용

REST는 신뢰할 수 있는 컨트롤러에만 활성화한 다음, 문서화된 어댑터 경로를 통해 aMuTorrent, Prowlarr, Radarr, Sonarr를 사용하세요.

03

증거 읽기

설정, API, 릴리스, SBOM, 패키지 세부 정보는 렌더링된 문서에 있으므로 공개된 주장은 버전 관리되는 증거에 묶인 채 유지됩니다.

광대역 릴리스 라인은 기존 WebServer 리스너에서 리소스 지향 /api/v1 JSON API를 제공합니다. X-API-Key로 인증하고, JSON 엔벨로프를 반환하며, 네이티브 eMule 상태 변경을 앱을 통해 처리하도록 유지합니다.

프로젝트 이야기

P2P 작업장 뒤의 노새 팀

01

업로드 노새 조련사

광대역 업로드 슬롯이 마구간 문을 걷어차지 못하게 막고, 느린 녀석들을 매우 공식적인 클립보드로 다시 줄 세웁니다.

02

Kad 산길 노새

bootstrap 노드, 라우팅 테이블, 고집스러운 eD2K/Kad 전승을 험한 네트워크 지형 너머로, 프로토콜 지도를 잃지 않고 운반합니다.

03

릴리스 짐 노새

무언가가 준비됐다고 불리기 전에 패키지, 해시, SBOM, 로그, 라이브 검사, 그리고 딱 적당한 태도를 게이트 너머로 끌고 갑니다.

보안과 출처

0.7.3은 GitHub에서 빌드되고 패키징됩니다

공개된 0.7.3

emulebb-v0.7.3은 x64 및 ARM64 ZIP, 진단 패키지, 매니페스트, SBOM, 스위트 부트스트래퍼를 포함한 GitHub 프리릴리스입니다.

해시 검증 설치

부트스트래퍼는 릴리스 자산을 다운로드하고 설치 전에 공개된 매니페스트로부터 패키지 해시를 검증합니다.

스위트 자산

대응하는 aMuTorrent 0.7.3 패키지는 별도로 공개되며, 전체 x64 부트스트랩 흐름이 컨트롤러 설정을 위해 이를 자동으로 해결합니다.

컨트롤러 증거

aMuTorrent, Prowlarr, Radarr, Sonarr, Torznab, 그리고 qBittorrent 호환 레인은 네이티브 /api/v1 계약을 중심으로 한 로컬 통합 경로로 문서화되어 있습니다.
