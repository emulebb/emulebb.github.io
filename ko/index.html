왜

P2P 소프트웨어는 실제 세션을 견뎌내며 신뢰를 얻습니다

eMuleBB는 제품적 노력이자 엔지니어링 실천입니다. 실제 네트워크 동작을 지닌 복잡한 네이티브 Windows 클라이언트를 보존하고, 그것을 현대적인 빌드, 테스트, 문서, 자동화, 릴리스 증거로 둘러쌉니다.

제품적 이유

eMuleBB는 독립적인 제품

목표는 겉모습만 바꾼 mod, 프로토콜 포크, 일반적인 다운로더 셸이 아닙니다. 긴 세션, 희귀한 파일, 의도적인 시딩, 그리고 여전히 네이티브 데스크톱 워크플로를 원하는 파워 유저를 위한 광대역 중심의 eMule 라인입니다.

엔지니어링 이유

P2P 동작을 검사 가능하게 만들기

업로드 슬롯, 타임아웃, 버퍼, 대규모 라이브러리, WebServer 노출, REST 제어, 패키지 증거를 명시적으로 만들어 각 변경을 검토·테스트·문서화·조정할 수 있게 합니다.

생태계 이유

클라이언트 주위에 도구를 구축하기

동일한 workspace 규율이 앱, 컨트롤러 도구, Windows 빌드, 결정적 eD2K 서비스, 실험적 헤드리스 eD2K/Kad 작업을 아우르며, 모든 실험 프로젝트가 안정적인 최종 사용자 제품인 척하지 않습니다.

기능

eMuleBB가 기존 클라이언트 주위에 더하는 것

The stable 0.7.3 line is focused on operator-visible behavior: predictable upload policy, safer binding, fixed performance limits, large-library operation, local automation, and package evidence.

공유 및 업로드

광대역 업로드 제어

한정된 슬롯 목표, 약한 슬롯 재활용, 비율 표시, 시딩 제어가 eD2K 업로드 프로토콜을 바꾸지 않고도 빠른 업로드 회선을 유용하게 유지합니다.

네트워크 제어

Binding, NAT, 노출 정책

인터페이스를 인식하는 binding, UPnP/NAT 매핑 검증, HTTPS, 허용 IP 규칙, 별도의 WebServer 바인드 설정이 원격 표면을 명시적이고 테스트 가능하게 유지합니다. binding은 VPN 킬 스위치가 아닙니다.

성능과 규모

대규모 세션을 위한 현대적 기본값

더 큰 소켓 버퍼, queue/source 한계, 파일 버퍼링, 타임아웃 기본값, 재귀 공유 동기화, 시작 시 캐시 작업, 긴 경로 안내가 현재의 Windows 시스템과 대규모 라이브러리를 대상으로 합니다.

클래식 네트워크

eD2K와 Kad가 우선

서버, 글로벌, Kad 검색은 네이티브 기반으로 남아 있으며, Kad 신원 추적, 불량 노드 처리, 정리, 타이밍 작업은 호환성 경계 안에 유지됩니다.

자동화

REST 및 컨트롤러 워크플로

인증된 JSON 엔드포인트는 신뢰된 로컬 도구로부터의 전송, 검색, 공유 파일, 서버, Kad, 로그, 카테고리, 업로드, 통계, 환경설정, 제어된 종료를 다룹니다.

테스트와 릴리스 규율

라벨보다 증거 먼저

0.7.3은 GitHub Actions 패키징, 매니페스트, SHA-256 증거, SPDX SBOM, 진단 자산, 부트스트래퍼 해시 증거와 함께 공개됩니다.

Security and provenance

0.7.3 is built and packaged on GitHub

Published 0.7.3

emulebb-v0.7.3 is a stable GitHub release with x64 and ARM64 ZIPs, diagnostics packages, manifests, SBOMs, and the suite bootstrapper.

Hash-checked setup

The bootstrapper downloads release assets and verifies package hashes from the published manifests before installing.

Suite assets

The matching aMuTorrent 0.7.3 companion package is published separately, and the full x64 bootstrap flow resolves it automatically for controller setup.

SPDX SBOM

Release packages carry package-local SBOM.spdx.json plus sidecar *.sbom.spdx.json files, with manifest hashes that tie software contents to the exact package evidence.

GitHub provenance

Stable 0.7.3 assets are published from GitHub release automation with manifests, SHA-256 evidence, SBOMs, and a bootstrapper hash asset for verification.

Controller proof

aMuTorrent, Prowlarr, Radarr, Sonarr, Torznab, and qBittorrent-compatible lanes are documented as local integration paths around the native /api/v1 contract.
