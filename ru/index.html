Кратко об eMuleBB

Nightlies → Beta 2 → MFC 0.7.3

eMuleBB Rust — активный бета-клиент eD2K/Kad; nightly-сборки являются основным каналом тестирования, Beta 2 — официальной базой, а MFC — поддерживаемой линией Windows.

Это дом eMuleBB: eMule broadband edition, независимого продукта для тех, кто всё ещё ценит распределённую модель обмена eMule и хочет управлять ею как современным ПО. Пакеты 0.7.3 опубликованы на GitHub Releases вместе с бутстраппером полного набора, отдельными ZIP, манифестами, хешами, SBOM и соответствующими ресурсами контроллера aMuTorrent.

Зачем

P2P-софт завоёвывает доверие, переживая реальные сессии

eMuleBB — это одновременно продуктовая работа и инженерная практика: сохранить сложный нативный клиент Windows с реальным сетевым поведением, а затем окружить его современными сборками, тестами, документацией, автоматизацией и доказательствами релиза.

Продуктовая причина

eMuleBB — это самостоятельный продукт

Цель — не косметический мод, не форк протокола и не обобщённая оболочка для загрузок. Это ориентированная на широкополосный доступ линейка eMule для длинных сессий, редких файлов, осознанного сидирования и опытных пользователей, которым всё ещё нужен нативный десктопный рабочий процесс.

Инженерная причина

Сделать поведение P2P проверяемым

Слоты отдачи, тайм-ауты, буферы, большие библиотеки, доступность WebServer, управление через REST и доказательства пакетов сделаны явными, чтобы каждое изменение можно было проверить, протестировать, задокументировать и настроить.

Причина экосистемы

Строить инструменты вокруг клиента

Та же дисциплина workspace охватывает клиент Rust, инструменты управления, нативные сборки, детерминированные сервисы eD2K, тесты в реальной сети и поддерживаемый клиент Windows.

Возможности

Что eMuleBB добавляет вокруг классического клиента

Работа над 0.7.3 сосредоточена на видимом оператору поведении: предсказуемая политика отдачи, более безопасный binding, фиксированные пределы производительности, работа с большими библиотеками, локальная автоматизация и доказательства пакетов.

Обмен и отдача

Широкополосный контроль отдачи

Ограниченные цели по слотам, переработка слабых слотов, показ рейтинга и управление сидированием сохраняют пользу быстрых каналов отдачи без изменения протокола отдачи eD2K.

Управление сетью

Binding, NAT и политика доступности

Binding с учётом интерфейса, проверка маппинга UPnP/NAT, HTTPS, правила разрешённых IP и отдельные настройки bind для WebServer держат удалённые поверхности явными и проверяемыми. Binding — это не VPN kill switch.

Производительность и масштаб

Современные значения по умолчанию для больших сессий

Увеличенные буферы сокетов, лимиты queue/source, файловая буферизация, значения тайм-аутов по умолчанию, рекурсивная синхронизация общих папок, работа кеша при запуске и рекомендации по длинным путям нацелены на современные системы Windows и большие библиотеки.

Классическая сеть

eD2K и Kad остаются на первом месте

Поиск по серверу, глобальный и Kad остаётся нативной основой, с отслеживанием идентичности Kad, обработкой плохих узлов, очисткой и работой над таймингом в пределах совместимости.

Автоматизация

Рабочие процессы REST и контроллеров

Аутентифицированные JSON-эндпоинты охватывают передачи, поиски, общие файлы, серверы, Kad, логи, категории, отдачи, статистику, настройки и контролируемое завершение работы из доверенных локальных инструментов.

Дисциплина тестирования и релизов

Доказательства прежде ярлыков

0.7.3 опубликован с упаковкой GitHub Actions, манифестами, доказательствами SHA-256, SBOM SPDX, ресурсами диагностики и доказательствами хеша бутстраппера.

Документация

Руководства, API и заметки о релизах

01

Начните с руководства по продукту

Сначала используйте eMuleBB как eMule: доверенные серверы, осознанный bootstrap Kad, предсказуемые пути incoming/temp и видимые общие папки.

02

Используйте локальную автоматизацию

Включайте REST только для доверенных контроллеров, затем используйте aMuTorrent, Prowlarr, Radarr и Sonarr через задокументированные пути адаптеров.

03

Читайте доказательства

Детали setup, API, релиза, SBOM и пакетов находятся в отрендеренной документации, так что публичные заявления остаются привязаны к доказательствам под контролем версий.

Широкополосная линия релизов предоставляет ресурсо-ориентированный JSON API /api/v1 через существующий listener WebServer. Он аутентифицируется через X-API-Key, отдаёт JSON-конверты и направляет нативные изменения состояния eMule через приложение.

Культура проекта

Команда мулов за P2P-мастерской

01

Укротитель мулов отдачи

Не даёт широкополосным слотам отдачи выбить дверь конюшни, а затем возвращает медленных в строй с очень официальным планшетом.

02

Мул тропы Kad

Несёт узлы bootstrap, таблицы маршрутизации и упрямый фольклор eD2K/Kad по неровной сетевой местности, не теряя карту протокола.

03

Вьючный мул релизов

Тащит пакеты, хеши, SBOM, логи, живые проверки и ровно столько характера через ворота, прежде чем что-то назовут готовым.

Безопасность и происхождение

0.7.3 собирается и упаковывается на GitHub

Опубликованный 0.7.3

emulebb-v0.7.3 — это предрелиз GitHub с ZIP для x64 и ARM64, пакетами диагностики, манифестами, SBOM и бутстраппером набора.

Установка с проверкой хеша

Бутстраппер скачивает ресурсы релиза и проверяет хеши пакетов по опубликованным манифестам перед установкой.

Ресурсы набора

Соответствующий пакет aMuTorrent 0.7.3 публикуется отдельно, а полный поток bootstrap для x64 разрешает его автоматически для настройки контроллера.

Доказательства контроллеров

aMuTorrent, Prowlarr, Radarr, Sonarr, Torznab и qBittorrent-совместимые маршруты задокументированы как локальные пути интеграции вокруг нативного контракта /api/v1.
