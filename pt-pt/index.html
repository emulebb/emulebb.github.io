Resumo do eMuleBB

Nightlies → Beta 2 → MFC 0.7.3

O eMuleBB Rust é o cliente beta eD2K/Kad ativo; as nightlies são o canal principal de testes, o Beta 2 é a referência formal e o MFC continua como linha Windows mantida.

Este é o lar do eMuleBB: eMule broadband edition, um produto independente para quem ainda valoriza o modelo de partilha distribuída do eMule e o quer operar como software moderno. Os pacotes 0.7.3 estão publicados no GitHub Releases com um bootstrapper de suíte completa, ZIPs autónomos, manifestos, hashes, SBOMs e os assets de controlador aMuTorrent correspondentes.

Porquê

O software P2P ganha confiança sobrevivendo a sessões reais

O eMuleBB é ao mesmo tempo um esforço de produto e uma prática de engenharia: preservar um cliente Windows nativo complexo com comportamento de rede real e depois rodeá-lo de builds, testes, documentação, automação e provas de release modernos.

Motivo de produto

O eMuleBB é um produto próprio

O objetivo não é um mod cosmético, um fork de protocolo nem uma casca de transferências genérica. É uma linha eMule focada em banda larga para sessões longas, ficheiros raros, seeding deliberado e utilizadores avançados que ainda querem o fluxo de ambiente de trabalho nativo.

Motivo técnico

Tornar o comportamento P2P inspecionável

Slots de upload, timeouts, buffers, grandes bibliotecas, exposição do WebServer, controlo REST e evidência de pacote são tornados explícitos para que cada alteração possa ser revista, testada, documentada e ajustada.

Motivo de ecossistema

Construir as ferramentas em torno do cliente

A mesma disciplina de workspace abrange o cliente Rust, o tooling de controladores, os builds nativos, os serviços eD2K determinísticos, os testes em rede real e o cliente Windows mantido.

Funcionalidades

O que o eMuleBB acrescenta em torno do cliente clássico

O trabalho do 0.7.3 foca o comportamento visível ao operador: política de upload previsível, binding mais seguro, limites fixos de desempenho, operação de grandes bibliotecas, automação local e evidência de pacote.

Partilha e upload

Controlo de upload em banda larga

Metas de slots limitadas, reciclagem de slots fracos, leituras de ratio e controlos de seeding mantêm úteis as ligações de upload rápidas sem alterar o protocolo de upload eD2K.

Controlo de rede

Binding, NAT e política de exposição

Binding consciente da interface, validação de mapeamento UPnP/NAT, HTTPS, regras de IP permitido e definições de bind do WebServer separadas mantêm as superfícies remotas explícitas e testáveis. Binding não é um kill switch de VPN.

Desempenho e escala

Predefinições atuais para sessões grandes

Buffers de socket maiores, limites de queue/source, file buffering, predefinições de timeout, sincronização recursiva de partilhas, trabalho de cache no arranque e orientação de long paths visam os sistemas Windows atuais e grandes bibliotecas.

Rede clássica

eD2K e Kad continuam em primeiro

A pesquisa Server, global e Kad continua a base nativa, com rastreio de identidade Kad, tratamento de nós maus, limpeza e trabalho de timing mantidos dentro dos limites de compatibilidade.

Automação

Fluxos REST e de controladores

Endpoints JSON autenticados cobrem transferências, pesquisas, ficheiros partilhados, servidores, Kad, logs, categorias, uploads, estatísticas, preferências e encerramento controlado a partir de ferramentas locais de confiança.

Disciplina de testes e release

Evidência antes de rótulos

0.7.3 está publicado com packaging do GitHub Actions, manifestos, evidência SHA-256, SBOMs SPDX, assets de diagnóstico e evidência de hash do bootstrapper.

Documentação

Guias, API e notas de release

01

Comece pelo guia do produto

Use o eMuleBB primeiro como eMule: servidores de confiança, bootstrap Kad deliberado, caminhos incoming/temp previsíveis e pastas partilhadas visíveis.

02

Use automação local

Ative o REST apenas para controladores de confiança e depois use aMuTorrent, Prowlarr, Radarr e Sonarr pelos caminhos de adaptador documentados.

03

Leia a evidência

Cultura do projeto

A equipa de mulas por trás da oficina P2P

01

Domador de mulas de upload

Impede que os slots de upload de banda larga deitem abaixo a porta do estábulo e repõe os lentos na linha com uma prancheta muito oficial.

02

Mula de trilho Kad

Transporta nós de bootstrap, tabelas de encaminhamento e o teimoso folclore eD2K/Kad por terreno de rede acidentado sem perder o mapa do protocolo.

03

Mula de carga das releases

Arrasta pacotes, hashes, SBOMs, logs, verificações em direto e atitude q.b. pelo portão antes de algo ser declarado pronto.

Segurança e proveniência

O 0.7.3 é construído e empacotado no GitHub

0.7.3 publicado

emulebb-v0.7.3 é uma prerelease do GitHub com ZIPs x64 e ARM64, pacotes de diagnóstico, manifestos, SBOMs e o bootstrapper da suíte.

Instalação verificada por hash

O bootstrapper transfere os assets do release e verifica os hashes dos pacotes a partir dos manifestos publicados antes de instalar.

Assets da suíte

O pacote aMuTorrent 0.7.3 correspondente é publicado separadamente, e o fluxo completo de bootstrap x64 resolve-o automaticamente para a configuração do controlador.

Prova dos controladores

aMuTorrent, Prowlarr, Radarr, Sonarr, Torznab e as vias compatíveis com qBittorrent estão documentados como caminhos de integração local em torno do contrato nativo /api/v1.
