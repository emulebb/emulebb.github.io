Навіщо

P2P-софт здобуває довіру, переживаючи реальні сесії

eMuleBB — це водночас продуктова робота й інженерна практика: зберегти складний нативний клієнт Windows із реальною мережевою поведінкою, а потім оточити його сучасними збірками, тестами, документацією, автоматизацією та доказами релізу.

Продуктова причина

eMuleBB — це самостійний продукт

Мета — не косметичний мод, не форк протоколу й не узагальнена оболонка для завантажень. Це орієнтована на широкосмуговий доступ лінійка eMule для довгих сесій, рідкісних файлів, свідомого сидування та досвідчених користувачів, яким досі потрібен нативний десктопний робочий процес.

Інженерна причина

Зробити поведінку P2P придатною до перевірки

Слоти віддачі, тайм-аути, буфери, великі бібліотеки, доступність WebServer, керування через REST і докази пакетів зроблено явними, щоб кожну зміну можна було переглянути, протестувати, задокументувати й налаштувати.

Причина екосистеми

Будувати інструменти навколо клієнта

Та сама дисципліна workspace охоплює застосунок, інструменти керування, збірки Windows, детерміновані сервіси eD2K та експериментальну headless-роботу eD2K/Kad, не вдаючи, що кожен лабораторний проєкт — стабільний продукт для кінцевого користувача.

Можливості

Що eMuleBB додає навколо класичного клієнта

Робота над RC1 зосереджена на видимій оператору поведінці: передбачувана політика віддачі, безпечніший binding, фіксовані межі продуктивності, робота з великими бібліотеками, локальна автоматизація та докази пакетів.

Обмін і віддача

Широкосмуговий контроль віддачі

Обмежені цілі за слотами, переробка слабких слотів, показ рейтингу та керування сидуванням зберігають корисність швидких каналів віддачі без зміни протоколу віддачі eD2K.

Керування мережею

Binding, NAT і політика доступності

Binding з урахуванням інтерфейсу, перевірка зіставлення UPnP/NAT, HTTPS, правила дозволених IP та окремі налаштування bind для WebServer тримають віддалені поверхні явними й придатними до тестування. Binding — це не VPN kill switch.

Продуктивність і масштаб

Сучасні типові значення для великих сесій

Більші буфери сокетів, ліміти queue/source, файлова буферизація, типові тайм-аути, рекурсивна синхронізація спільних папок, робота кешу під час запуску й настанови щодо довгих шляхів націлені на сучасні системи Windows і великі бібліотеки.

Класична мережа

eD2K і Kad лишаються на першому місці

Пошук через сервер, глобальний і Kad лишається нативною основою, із відстеженням ідентичності Kad, обробкою поганих вузлів, очищенням і роботою над таймінгом у межах сумісності.

Автоматизація

Робочі процеси REST і контролерів

Автентифіковані JSON-ендпоінти охоплюють передачі, пошуки, спільні файли, сервери, Kad, журнали, категорії, віддачі, статистику, налаштування та контрольоване завершення роботи з довірених локальних інструментів.

Документація

Посібники, API та нотатки до релізів

01

Почніть із посібника з продукту

Спершу використовуйте eMuleBB як eMule: довірені сервери, свідомий bootstrap Kad, передбачувані шляхи incoming/temp і видимі спільні теки.

02

Використовуйте локальну автоматизацію

Вмикайте REST лише для довірених контролерів, а потім використовуйте aMuTorrent, Prowlarr, Radarr та Sonarr через задокументовані шляхи адаптерів.

03

Читайте докази

Деталі налаштування, API, релізу, SBOM і пакетів містяться у відрендереній документації, тож публічні твердження лишаються прив'язаними до доказів під контролем версій.

Широкосмугова лінія релізів надає ресурсо-орієнтований JSON API /api/v1 через наявний слухач WebServer. Він автентифікує через X-API-Key, повертає JSON-конверти й тримає нативні зміни стану eMule спрямованими через застосунок.

Культура проєкту

Команда мулів за P2P-майстернею

01

Приборкувач мулів віддачі

Не дає широкосмуговим слотам віддачі вибити двері стайні, а потім повертає повільних у шеренгу з дуже офіційним планшетом.

02

Мул стежки Kad

Несе вузли bootstrap, таблиці маршрутизації та впертий фольклор eD2K/Kad через нерівний мережевий рельєф, не гублячи карту протоколу.

03

В'ючний мул релізів

Тягне пакети, хеші, SBOM, журнали, живі перевірки й рівно стільки характеру крізь браму, перш ніж щось назвуть готовим.

Безпека й походження

RC1 збирається й пакується на GitHub

Опублікований RC1

emulebb-v0.7.3-rc.1 — це попередній випуск GitHub із ZIP для x64 і ARM64, пакетами діагностики, маніфестами, SBOM і бутстрапером набору.

Встановлення з перевіркою хешу

Бутстрапер завантажує ресурси релізу й перевіряє хеші пакетів за опублікованими маніфестами перед встановленням.

Ресурси набору

Відповідний пакет aMuTorrent RC1 публікується окремо, а повний потік bootstrap для x64 розв'язує його автоматично для налаштування контролера.

SPDX SBOM

Release packages carry package-local SBOM.spdx.json plus sidecar *.sbom.spdx.json files, with manifest hashes that tie software contents to the exact package evidence.

GitHub provenance

RC1 assets are published from GitHub release automation with manifests, SHA-256 evidence, SBOMs, and a bootstrapper hash asset for verification.

Докази контролерів

aMuTorrent, Prowlarr, Radarr, Sonarr, Torznab і сумісні з qBittorrent маршрути задокументовано як локальні шляхи інтеграції навколо нативного контракту /api/v1.
