To dom eMuleBB: eMule broadband edition, niezależnego produktu dla osób, które wciąż cenią rozproszony model udostępniania eMule i chcą go obsługiwać jak nowoczesne oprogramowanie. Paczki RC1 są opublikowane w GitHub Releases wraz z bootstrapperem pełnego pakietu, samodzielnymi ZIP-ami, manifestami, hashami, SBOM-ami i odpowiadającymi zasobami kontrolera aMuTorrent.

Dlaczego

Oprogramowanie P2P zdobywa zaufanie, przetrwając prawdziwe sesje

eMuleBB to jednocześnie praca produktowa i praktyka inżynierska: zachować złożonego natywnego klienta Windows o realnym zachowaniu sieciowym, a następnie otoczyć go nowoczesnymi buildami, testami, dokumentacją, automatyzacją i dowodami wydania.

Powód produktowy

eMuleBB to osobny produkt

Celem nie jest kosmetyczny mod, fork protokołu ani ogólna powłoka do pobierania. To zorientowana na łącza szerokopasmowe linia eMule dla długich sesji, rzadkich plików, świadomego seedowania i zaawansowanych użytkowników, którzy wciąż chcą natywnego przepływu desktopowego.

Powód techniczny

Uczynić zachowanie P2P możliwym do zbadania

Sloty uploadu, timeouty, bufory, duże biblioteki, ekspozycja WebServera, kontrola REST i dowody paczek są jawne, aby każdą zmianę można było przejrzeć, przetestować, udokumentować i dostroić.

Powód ekosystemowy

Zbuduj narzędzia wokół klienta

Ta sama dyscyplina workspace'a obejmuje aplikację, narzędzia sterujące, buildy Windows, deterministyczne usługi eD2K i eksperymentalną pracę headless eD2K/Kad, bez udawania, że każdy projekt laboratoryjny jest stabilnym produktem dla użytkownika końcowego.

Funkcje

Co eMuleBB dodaje wokół klasycznego klienta

Prace nad RC1 skupiają się na zachowaniu widocznym dla operatora: przewidywalna polityka uploadu, bezpieczniejszy binding, stałe limity wydajności, obsługa dużych bibliotek, lokalna automatyzacja i dowody paczek.

Udostępnianie i upload

Szerokopasmowa kontrola uploadu

Ograniczone cele slotów, recykling słabych slotów, odczyty ratio i sterowanie seedowaniem utrzymują przydatność szybkich łączy uploadu bez zmiany protokołu uploadu eD2K.

Kontrola sieci

Binding, NAT i polityka ekspozycji

Binding świadomy interfejsu, walidacja mapowania UPnP/NAT, HTTPS, reguły dozwolonych IP i osobne ustawienia bindowania WebServera utrzymują zdalne powierzchnie jawnymi i testowalnymi. Binding to nie kill switch VPN.

Wydajność i skala

Nowoczesne wartości domyślne dla dużych sesji

Większe bufory gniazd, limity queue/source, buforowanie plików, domyślne timeouty, rekurencyjna synchronizacja udziałów, praca cache startowego i wskazówki dotyczące długich ścieżek celują w obecne systemy Windows i duże biblioteki.

Klasyczna sieć

eD2K i Kad pozostają na pierwszym miejscu

Wyszukiwanie Server, globalne i Kad pozostaje natywną podstawą, z śledzeniem tożsamości Kad, obsługą złych węzłów, czyszczeniem i pracą nad timingiem w granicach zgodności.

Automatyzacja

Przepływy REST i kontrolerów

Uwierzytelnione endpointy JSON obejmują transfery, wyszukiwania, udostępniane pliki, serwery, Kad, logi, kategorie, uploady, statystyki, preferencje i kontrolowane zamykanie z zaufanych narzędzi lokalnych.

SPDX SBOM

Release packages carry package-local SBOM.spdx.json plus sidecar *.sbom.spdx.json files, with manifest hashes that tie software contents to the exact package evidence.

GitHub provenance

RC1 assets are published from GitHub release automation with manifests, SHA-256 evidence, SBOMs, and a bootstrapper hash asset for verification.
