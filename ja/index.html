eMuleBB の概要

Nightlies → Beta 2 → MFC 0.7.3

eMuleBB Rust は開発中の eD2K/Kad beta クライアントです。nightly が主要なテスト経路、Beta 2 が正式な基準、MFC が保守中の Windows ラインです。

ここは eMuleBB の拠点です。eMule broadband edition は、eMule の分散共有モデルを今も大切にし、それを現代的なソフトウェアのように運用したい人のための独立した製品です。0.7.3 パッケージは、フルスイートのブートストラッパー、スタンドアロン ZIP、マニフェスト、ハッシュ、SBOM、そして対応する aMuTorrent コントローラーのアセットとともに GitHub Releases で公開されています。

なぜ

P2P ソフトウェアは実際のセッションを生き延びることで信頼を得る

eMuleBB は製品としての取り組みであり、同時にエンジニアリングの実践でもあります。実際のネットワーク挙動を持つ複雑なネイティブ Windows クライアントを保ちつつ、現代的なビルド、テスト、ドキュメント、自動化、リリース証跡で取り囲みます。

製品上の理由

eMuleBB は独立した製品

目標は見た目だけの mod、プロトコルのフォーク、汎用ダウンローダーのシェルではありません。長時間のセッション、希少なファイル、意図的なシード、そして今もネイティブのデスクトップワークフローを望むパワーユーザーのための、ブロードバンド志向の eMule ラインです。

技術上の理由

P2P の挙動を検査可能にする

アップロードスロット、タイムアウト、バッファ、大規模ライブラリ、WebServer の公開、REST 制御、パッケージ証跡を明示的にすることで、各変更をレビュー・テスト・文書化・調整できるようにします。

エコシステム上の理由

クライアントの周りにツールを構築する

同じ workspace の規律が、Rust クライアント、コントローラーツール、ネイティブビルド、決定的な eD2K サービス、実ネットワークテスト、保守中の Windows クライアントをカバーします。

機能

eMuleBB が従来のクライアントの周りに加えるもの

0.7.3 の作業は運用者に見える挙動に焦点を当てています。予測可能なアップロードポリシー、より安全な binding、固定された性能上限、大規模ライブラリの運用、ローカル自動化、そしてパッケージ証跡です。

共有とアップロード

ブロードバンドのアップロード制御

上限付きのスロット目標、弱いスロットのリサイクル、レシオ表示、シード制御により、eD2K アップロードプロトコルを変えずに高速アップロード回線を有用に保ちます。

ネットワーク制御

Binding、NAT、公開ポリシー

インターフェースを意識した binding、UPnP/NAT マッピング検証、HTTPS、許可 IP ルール、独立した WebServer のバインド設定により、リモート面を明示的かつテスト可能に保ちます。binding は VPN のキルスイッチではありません。

性能とスケール

大規模セッション向けの現代的な既定値

より大きなソケットバッファ、queue/source の上限、ファイルバッファリング、タイムアウト既定値、再帰的な共有同期、起動時キャッシュ処理、長いパスの指針が、現在の Windows システムと大規模ライブラリを対象とします。

従来のネットワーク

eD2K と Kad が最優先のまま

サーバー検索、グローバル検索、Kad 検索はネイティブの基盤であり続け、Kad のアイデンティティ追跡、不良ノード処理、クリーンアップ、タイミング作業は互換性の境界内に保たれます。

自動化

REST とコントローラーのワークフロー

認証付き JSON エンドポイントは、信頼されたローカルツールからの転送、検索、共有ファイル、サーバー、Kad、ログ、カテゴリ、アップロード、統計、設定、制御されたシャットダウンをカバーします。

テストとリリースの規律

ラベルより先に証跡

0.7.3 は、GitHub Actions によるパッケージング、マニフェスト、SHA-256 証跡、SPDX SBOM、診断アセット、ブートストラッパーのハッシュ証跡とともに公開されています。

ドキュメント

ガイド、API、リリースノート

01

製品ガイドから始める

まず eMuleBB を eMule として使います。信頼できるサーバー、意図的な Kad bootstrap、予測可能な incoming/temp のパス、見える共有フォルダーです。

02

ローカル自動化を使う

REST は信頼できるコントローラーに対してのみ有効にし、文書化されたアダプター経路を通じて aMuTorrent、Prowlarr、Radarr、Sonarr を使います。

03

証跡を読む

セットアップ、API、リリース、SBOM、パッケージの詳細はレンダリング済みのドキュメントにあり、公開された主張はバージョン管理された証跡に結び付いたままになります。

ブロードバンドのリリースラインは、既存の WebServer リスナーからリソース指向の /api/v1 JSON API を公開します。X-API-Key で認証し、JSON エンベロープを返し、ネイティブの eMule 状態変更をアプリ経由で取り扱い続けます。

プロジェクトの伝承

P2P 工房を支えるラバチーム

01

アップロード・ラバ使い

ブロードバンドのアップロードスロットが厩舎の扉を蹴破らないようにし、遅い者たちを非常に公式なクリップボードで列に戻します。

02

Kad 山道のラバ

bootstrap ノード、ルーティングテーブル、頑固な eD2K/Kad の言い伝えを、険しいネットワークの地形を越えて、プロトコルの地図を落とさずに運びます。

03

リリースの荷運びラバ

何かが準備完了と呼ばれる前に、パッケージ、ハッシュ、SBOM、ログ、ライブチェック、そしてちょうどよい態度をゲートの向こうへ運びます。

セキュリティと来歴

0.7.3 は GitHub でビルド・パッケージ化される

公開された 0.7.3

emulebb-v0.7.3 は、x64 と ARM64 の ZIP、診断パッケージ、マニフェスト、SBOM、スイートブートストラッパーを含む GitHub プレリリースです。

ハッシュ検証付きセットアップ

ブートストラッパーはリリースアセットをダウンロードし、インストール前に公開されたマニフェストからパッケージのハッシュを検証します。

スイートアセット

対応する aMuTorrent 0.7.3 パッケージは別途公開され、完全な x64 ブートストラップフローがコントローラー設定のためにそれを自動的に解決します。

コントローラーの証跡

aMuTorrent、Prowlarr、Radarr、Sonarr、Torznab、そして qBittorrent 互換のレーンは、ネイティブの /api/v1 契約を中心としたローカル統合経路として文書化されています。
